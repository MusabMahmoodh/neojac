# E50xx: refusals

These codes are reported for programs that parse and whose names resolve, but that neojac cannot
build as written: a class hierarchy with no consistent order, a construct that is not implemented
yet, a filter or an intrinsic call in a shape that has no meaning. In a template, `{name}` is
filled in when the error is reported.

## E5030

```text
cannot create a consistent method resolution order (MRO) for the bases of {name}
```

The archetype `{name}` lists its bases in an order that contradicts the order the bases themselves
set. A method is looked up in an archetype, then in its bases from left to right, and a base always
comes before its own bases; listing a base before one of its descendants asks for both orders at
once.

```jac
# expect: E5030
obj A {}

obj B(A) {}

obj C(A, B) {}
```

**Fix:** list the more derived base first, or drop the base that another base already brings in.
See [Inheritance](../../language/inheritance.md).

```jac
obj A {}

obj B(A) {}

obj C(B, A) {}

with entry {
    print(1);
}
```

## E5090

```text
neojac does not support {what} yet
```

The program uses part of the language that neojac does not implement. `{what}` names the construct
in plain words, for example `an import here` (an import in a function of a Python module the
native library does not have), `JSX` (JSX in a native module) or an enum member that repeats an earlier member's value. neojac refuses such a program
instead of building something with another meaning.

```jac
# expect: E5090
def main {
    import dis;
    print(dis.opname[0]);
}
```

**Fix:** write the program without the construct `{what}` names. Here, the program uses a module
of Python's that a native program does not have: run it in a `cpython` space, where Python loads
it ([Classes and decorators in a cpython space](../../interop/python-classes.md#an-import-in-a-code-body)).

An extension module's build meets it too
([Extension modules](../../toolchain/packages.md#extension-modules)):

- **An addon that registers itself from a static constructor**, as V8's `NODE_MODULE`, NAN and
  older Node-API headers make one: its objects define no `napi_register_module_v1` and call
  Node's registrar instead. It is reported at the addon's row in `jac.toml`, and nothing is
  written.

  ```toml
  [project]
  name = "seven"

  [c.addon]
  sources = ["seven.c"]
  include = ["{lib}/node/include/node"]

  [extensions."web/build/Release/seven"]
  c = "addon"

  [npm.web]
  private = true
  ```

  ```text
  jac.toml:9:1: error[E5090]: neojac does not support an addon that registers itself from a static constructor (as V8's NODE_MODULE, NAN and older Node-API headers make one; NAPI_MODULE_INIT defines Node-API's entry 'napi_register_module_v1' instead), as 'web/build/Release/seven' does through Node's 'node_module_register' yet
  ```

  **Fix:** define the entry with `NAPI_MODULE_INIT`. A library that merely lacks its row's
  `exports` is [E5271](e51-2.md#e5271).
- **An addon built from its C and C++ for another system than this one**,
  `neojac build web/package.json --target linux-aarch64` on macOS:

  ```text
  error[E5090]: neojac does not support building an extension module from its C and C++ for another system than this one ('web/build/Release/seven' for linux-aarch64, on macos-aarch64: the Jac `neojac port` writes of its files builds for any target) yet
  ```

  **Fix:** build it on the system it is for, or port its files
  ([port](../../toolchain/port.md#in-a-project)): built from the Jac, it builds for any target.

## E5094

```text
a filter {reason}
```

A filter (`items[?name op value]`, `items[?:Type]`) is malformed. `{reason}` is
`needs something to filter` for a filter written with no value before its `[`, or
`condition compares an attribute: ` followed by the form, `name op value`, for a condition that is
not a comparison with an attribute's name on its left.

```jac
# expect: E5094
obj P {
    has n: int = 0;
}

with entry {
    print(len([?n > 1]));
}
```

**Fix:** write the filter directly after the list it filters, and give each condition the item's
attribute on the left of a comparison.

```jac
obj P {
    has n: int = 0;
}

with entry {
    ps = [P(n=1), P(n=2)];
    print(len(ps[?n > 1]));
}
```

```output
1
```

## E5095

```text
invalid call to the intrinsic '{name}': {reason}
```

An intrinsic is a builtin that the compiler turns into machine operations directly, such as the
`__atomic_...` family. `{name}` is the intrinsic called and `{reason}` the rule the call breaks: an
argument that must be a constant, a value of the wrong kind, a memory order the operation cannot
use. In the example, an atomic load is given memory order 3 (release), which a load cannot use.

```jac
# expect: E5095
import from c {
    def malloc(n: int) -> int;
}

with entry {
    p = malloc(8);
    print(__atomic_load_i64(p, 3));
}
```

**Fix:** call the intrinsic with the arguments `{reason}` asks for. A memory order is a constant
from 0 (relaxed) to 5 (sequentially consistent); a load takes any but 3 and 4.

```jac
import from c {
    def malloc(n: int) -> int;
}

with entry {
    p = malloc(8);
    print(__atomic_load_i64(p, 5));
}
```
